DivineeSoft HRM: Task & Subtask System Audit Report

Target Audience: Product Owners, Project Stakeholders, and Clients
System Area: Task Register, Subtasks / Action Items, My Tasks Board, and Calendar Workflows
Date: November 2026
Status: Action Required Before Production Release

Executive Summary

A comprehensive quality, security, and usability review was conducted on the Task & Subtask Management System in DivineeSoft HRM.

While the core functionality (creating tasks, breaking work into action items, assigning contributors, and tracking status) provides a solid foundation, the audit identified 12 key issues across four categories:

  1. Data Loss & Frustration Bugs: Scenarios where user edits, dates, or checklist items are unintentionally lost or modified by the system.
  2. Access Control & Permissions Gaps: Inconsistencies where assignees are blocked from updating their own items, or unauthorized users have excessive deletion power.
  3. Workflow & Progress Inconsistencies: Disconnects where task progress percentages and completion states fall out of sync with checklist items.
  4. User Experience & Interface Polish: Visual badges missing from views, sticky form fields, and shared note inputs causing accidental cross-task contamination.

None of these issues require a rebuild of the application. They can all be resolved with focused refinements to the business rules and user interface components.

1. High-Priority Issues (Immediate Action Required)

1.1 The "Typing Reset" Glitch in Task Edit Dialog

  • Where It Happens: When clicking "Edit" on a task from the Task Register.
  • What the User Experiences: A user opens the task edit window and starts typing notes or editing the title. Within half a second, the window suddenly flashes and wipes out whatever the user was typing, resetting the form back to its original state.
  • Why It Matters: High frustration and data loss. Users lose their typed thoughts and feel the application is unstable or laggy.
  • What Causes It: The window loads basic task info immediately, but fetches detailed updates a split second later in the background. When the background data arrives, it forces the entire window to re-initialize and discard active typing.
  • Recommended Solution: Load all necessary details before displaying the edit form, or lock the form fields so background refreshes never overwrite active user input.

1.2 Team Members Blocked from Checking Off Their Own Subtasks

  • Where It Happens: When a team member attempts to check off a subtask assigned to them.
  • What the User Experiences: If Manager A creates a task and delegates Subtask 1 to Employee B, Employee B sees an error message: "You can only change tasks you own or manage" when clicking the completion checkbox.
  • Why It Matters: Defeats the core purpose of delegating subtasks. Team members cannot report completed work themselves; only the manager can check off items.
  • What Causes It: The security check verifies whether the employee has edit rights to the entire parent task, rather than recognizing that they are the assigned owner of that specific action item.
  • Recommended Solution: Allow any employee explicitly assigned to a subtask to mark that subtask complete or incomplete.

1.3 Subtask Checklist Badge Missing from the Task Register Table

  • Where It Happens: In the main Task Register list view.
  • What the User Experiences: In the Task Register table, tasks that contain subtasks do not show any indicator or badge (e.g., 2/5 checklist done). The column shows only the task title and project.
  • Why It Matters: Managers and team leads cannot see which tasks have checklists or their completion rate without opening each task one by one.
  • What Causes It: The badge was designed in the user interface, but the data pipeline that populates the live table inadvertently drops the subtask list during data transfer.
  • Recommended Solution: Ensure the live table data includes subtask counts and completion ratios so the progress badge displays properly.

1.4 Date Shifting Backward by One Day Across Timezones

  • Where It Happens: When setting task start dates and deadlines in local company timezones.
  • What the User Experiences: A user schedules a task for November 17. After saving and reopening the task later, the start date has shifted to November 16. Saving again moves it to November 15.
  • Why It Matters: Causes scheduling errors, missed deadlines, and calendar discrepancies across the team.
  • What Causes It: When dates are saved, midnight local time is converted to Universal Coordinated Time (UTC). In timezones east of UTC, this converts to the prior evening. When loaded back into the calendar, the application reads the UTC day instead of the original local day.
  • Recommended Solution: Store and display calendar dates using company-local calendar day values rather than raw UTC timestamps.

2. Business Logic & Workflow Gaps

2.1 Progress Percentage vs. Status Desynchronization

  • What Happens:
    1. If a task has 4 subtasks and all 4 are checked off, the task automatically marks itself as Completed (100%).
    2. If the user realizes one item was checked by mistake and unchecks it, the progress drops to 75%, but the task status remains marked as "Completed".
    3. Conversely, if a user clicks "Mark complete" directly on the parent task, progress sets to 100%, but all individual subtasks remain unchecked (0 of 4 done).
  • Why It Matters: Confusing and conflicting reporting. Reports show tasks marked "Completed" with incomplete checklists, or tasks marked "In Progress" with 100% progress.
  • Recommended Solution:
    • When a subtask is unchecked on a completed task, prompt or automatically adjust status back to In Progress.
    • When a user marks a task complete directly, offer to auto-complete remaining subtasks.

2.2 Delegated Subtasks Not Visible on Personal "My Tasks" Boards

  • What Happens: When an employee visits their personal command center ("My Tasks"), they only see tasks where they are the primary task owner. If they have been assigned action items under a project task owned by someone else, those items do not appear on their board.
  • What Happens to the CEO: The CEO's board currently only retrieves private personal tasks, filtering out regular business tasks assigned to the CEO.
  • Why It Matters: Team members lose track of work assigned to them. Managers assume employees see their delegated checklist items, while employees have no central visibility of them.
  • Recommended Solution: Update the personal board query so employees see both tasks they own and tasks containing subtasks assigned to them.

2.3 Regular Assignees Can Permanently Delete Entire Tasks

  • What Happens: Any employee assigned to a task has the ability to permanently delete the entire task via API actions, wiping out all subtasks, historical updates, and calendar blocks.
  • Why It Matters: Accidental or unauthorized deletion of business records. In an HR/Operations system, task deletion should be restricted to managers, project leads, or the creator of the task.
  • Recommended Solution: Allow assignees to update progress, add comments, and complete tasks, but restrict task deletion strictly to Management and the original task author.

3. User Experience & Interface Polish

3.1 Notes & Comments Shared Across Cards on the Task Board

  • What Happens: On the Kanban / Task Board, if a user opens Task A, types a blocker note or comment, and then opens Task B, the draft text from Task A remains in the input field on Task B.
  • Why It Matters: High risk of posting confidential or incorrect comments to the wrong task card.
  • Recommended Solution: Keep form inputs isolated to each individual task card so text typed on one card never leaks into another.

3.2 Inability to Rename Existing Subtasks in the Edit Dialog

  • What Happens: In the Task Edit dialog, existing subtasks can have their completion toggled, assignee changed, or deadline updated, but the title text itself cannot be edited.
  • Why It Matters: If someone makes a typo or wants to clarify a checklist item, they are forced to delete the item and recreate it from scratch.
  • Recommended Solution: Provide an editable text field or inline edit button for subtask titles.

3.3 Subtask Assignee Dropdown Sticking to Previous Selection

  • What Happens: When creating a task with multiple subtasks, assigning Employee A to the first subtask leaves Employee A selected for the next subtask.
  • Why It Matters: Subsequent checklist items get inadvertently assigned to Employee A unless the user manually resets the dropdown each time.
  • Recommended Solution: Automatically reset the subtask assignee dropdown to "Unassigned" after each item is added to the list.

3.4 Missing Visual Feedback When Toggling Subtasks

  • What Happens: When clicking a subtask checkbox on the board or in the calendar view, there is a 300–500 millisecond delay before the checkmark appears or line-through activates, with no loading spinner.
  • Why It Matters: Users assume the click did not register and click again, leading to double-toggles or frustration.
  • Recommended Solution: Implement instant visual feedback (optimistic update) so the checkbox ticks immediately while the server saves in the background.

4. Prioritized Action & Implementation Plan

Phase 1: High-Impact Stability Fixes (Estimated: 1–2 Days)

  1. Fix Edit Modal Input Wiping: Prevent background data refetching from clearing user input in TaskEditModal.tsx.
  2. Restore Subtask Badges: Map subtask counts in TaskClient.tsx so the register table shows {completed}/{total} badges.
  3. Resolve Timezone Date Drift: Standardize dates to company timezone calendar days across TaskComposer.tsx and TaskEditModal.tsx.

Phase 2: Permissions & Workflow Synchronization (Estimated: 2–3 Days)

  1. Enable Subtask Assignee Completion: Permit assigned employees to toggle subtask status in [id]/route.ts.
  2. Harmonize Status & Progress Rules: Auto-reopen completed tasks if subtasks are unchecked, and handle full completions gracefully.
  3. Protect Against Unauthorized Deletions: Guard DELETE /api/tasks/[id] so only Managers and Creators can remove tasks.
  4. Cross-Task Subtask ID Isolation: Ensure subtask edits cannot accidentally reference or update subtasks from other tasks.

Phase 3: Dashboard & Usability Polish (Estimated: 1–2 Days)

  1. Personal Board Subtask Visibility: Include delegated action items on employee personal dashboards.
  2. Card State Isolation on Task Board: Make comments and blocker fields private to each task card.
  3. Inline Subtask Title Editing: Allow title editing for existing subtasks in the modal.
  4. Instant Checkbox Feedback: Add optimistic UI updates on subtask check action.

Conclusion & Business Value

Addressing these items will transition the Task & Subtask module from a functioning prototype to an enterprise-grade workflow tool. The improvements will:

  • Eliminate user frustration caused by lost form data and shifting calendar dates.
  • Empower team members to manage and report on their delegated responsibilities without administrative bottlenecks.
  • Provide management with reliable, accurate project visibility where task statuses match checklist reality.
